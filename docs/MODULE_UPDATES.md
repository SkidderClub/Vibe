# Inventory, building and model changes

- Inventory Manager plans sword placement first, then armour equipment/upgrades, then other layout assignments and cleanup. Armour can equip even without an explicit layout entry. Drop Duplicates keeps one best item per tool/armour type, including ties and already equipped armour; ignored slots remain protected. Tools include material quality and Efficiency in their score.
- ChestStealer's Check Title accepts any displayed title containing `chest`, case-insensitively, including custom titles.
- BedAura refreshes its ray and target rotation after player movement and before the walking packet. It continues through the existing vanilla mining controller and idle-mining guard, preserving swing/dig and slot synchronization. Movement is no longer compared against an aim computed before movement. Public protocol references: [Grim packet order checks](https://github.com/GrimAnticheat/Grim/tree/2.0/common/src/main/java/ac/grim/grimac/checks/impl/packetorder). Local tests cover movement and the swing-before-start order; they do not certify a live Grim deployment.
- Scaffold adds **Start Options** (Sneak, Faster Rotate), a 1.0–5.0 **Start Rotation Multiplier**, **Less Micro Adjustments**, and **Sneak on Fail** when regular Sneak is off. Start actions stop after initial alignment. Normal/GodBridge keep the chosen side through a larger middle band; the Hypixel ground profile uses the same wider tolerance. Less Micro holds valid aim, suppresses optional yaw jitter, and changes pitch when the face can no longer be hit. Sneak on Fail tests support at the predicted next step and releases when support returns.
- TickBase defaults to **Screenshot**. A brief real pause (50 ms per selected tick, capped at 250 ms) lets vanilla's timer catch up, using collision-checked movement prediction and a cooldown. It does not add recursive ticks, fake movement packets, or alter keepalive replies in this mode. **Burst** retains the previous behavior for existing use cases. Actual movement depends on held inputs, world state and server behavior; no live Grim acceptance claim is made.

All settings are saved only through the explicit config save workflow. See [custom model settings](CUSTOM_MODELS.md) for per-sword mappings, cape hiding and the curated character catalogue.
